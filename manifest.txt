# Jailbreak Store autoloader — payload manifest
#
# This file decides which payloads the autoloader sends to elfldr, and in what
# order. It is read at runtime by src/boot.js, not just displayed.
#
# Resolution order at runtime:
#
#   1. /data/autoldr/manifest.txt on the console, if you have one - it wins
#   2. this file, fetched from the site origin
#   3. a built-in fallback of the three bundled payloads
#
# Everything here is fetched over HTTP from this site. You do not have to edit
# this file to pick your own plugins: drop a manifest at /data/autoldr/manifest.txt
# on the console and it replaces this one entirely. See "personal plugins" below.
#
# Format: one "name=target" per line. Blank lines and lines starting with # are
# ignored, as is anything after a # on a line. A bare "name" with no "=" is
# treated as payloads/<name>.
#
# A target is one of three things:
#
#   payloads/<file>        a file on this site
#   http(s)://host/<file>  a payload hosted anywhere else
#   local:/data/autoldr/f  a payload already sitting on the console
#
# A "//host/path" target is taken as https. Any other scheme is rejected and the
# run fails on it, so a typo cannot quietly become a path on this site.
#
# A remote host has to send Access-Control-Allow-Origin, or the WebView fetch
# fails and the run reports the URL that would not load.
#
# A local: target is opened on the console after the kernel stage, which is the
# only point where the chain can read a file at all. Only paths under
# /data/autoldr/ are reachable - anything else is rejected, and so is a ".."
# segment, which the kernel would otherwise resolve after the prefix check -
# and the file has to be on the console before the run starts, because this site
# has no way to put it there. A local payload costs the same as a fetched one:
# it is mapped in ROP memory and streamed to elfldr either way, so the bytes
# never reach the page.
#
# ORDER MATTERS, and the gap between payloads matters more.
#
# etaHEN starts its FTP server the moment it lands, and shadowmountplus remounts
# /system_ex. Sending those two close together panicked the console, so the
# loader waits ?payloadDelay= seconds (default 5) between entries. If you add
# payloads, keep the ones that touch mounts or network services apart.

# --- default: kstuff-lite, for firmware above 10.01 ---
kstuff-lite.elf=payloads/kstuff-lite-1.11B.elf

# --- etaHEN second, on its own, so its FTP server comes up settled ---
etahen.elf=payloads/etaHEN.elf


# --- shadowmountplus: it remounts /system_ex, so it goes after the rest ---
shadowmountplus.elf=payloads/shadowmountplus.elf

# --- alternative: full kstuff, for firmware 10.01 and below ---
# kstuff.elf=payloads/kstuff.elf
# etahen.elf=payloads/etaHEN.elf
# shadowmountplus.elf=payloads/shadowmountplus.elf

# --- a payload from somewhere else entirely, if a host will serve it ---
# Prospector.elf=https://example.com/payloads/Prospector.elf

# --- a payload dropped on the console beforehand, no host needed ---
# ProsperoMgr.elf=local:/data/autoldr/ProsperoMgr.elf

# ============================================================================
# PERSONAL PLUGINS: /data/autoldr/manifest.txt on the console
#
# Put your own entries in that file and it REPLACES this one - your list, your
# order, your plugins. Same format, same three target forms, including local:
# for ELFs you dropped on the console. Nothing else from this file is loaded
# once yours exists, so if you want etaHEN you name it yourself.
#
#   /data/autoldr/manifest.txt:
#     # my own stuff
#     ProsperoMgr.elf=local:/data/autoldr/plugins/ProsperoMgr.elf
#     etahen.elf=payloads/etaHEN.elf
#
# kstuff is the exception: it always loads first, because it is the payload that
# makes the rest work, and you do not have to name it. Which build is decided by
# firmware - full kstuff up to and including 10.01, kstuff-lite above that. Name
# kstuff.elf or kstuff-lite.elf yourself and that one is used instead, so you can
# pin a build:
#
#   kstuff-lite.elf=payloads/kstuff-lite-1.11B.elf
#
# It is read after the kernel stage, which is the first point the chain can read
# the console's filesystem at all. A missing file is normal and changes nothing.
# A file that is there but names something invalid fails the run, the same as a
# bad line here, so a typo cannot look like a successful run.
#
# Since your list replaces this one, the ordering note above is yours to get
# right: shadowmountplus remounts /system_ex, and the console panics when the
# things that touch mounts and network servers land close together. Keep it
# last, and remember ?payloadDelay= applies between every entry.
# ============================================================================
